## Intake

### Original request

> 创建 source 先选择 connector 再进入表单填写。connector 有个卡片列表。包含图标/标题/标签。表单填写区域应该左右布局。左边是表单。右边是 connector 的帮助文档（可以先留个位置）。表单 ... 从 spec json 里面获取。spec 里面 text 是个 json 字符串。parse 之后获取 configOptions.connection 就是表单 schema 了。

### Goals

- Preserve the existing Source detail interaction without changing its route or controls.
- Make creation a two-step dialog: select a connector card, then author the Source.
- Use `ConnectorDetail.spec.text`, parsed as JSON, and `configOptions.connection` as the Formily schema source.
- Show a right-side documentation placeholder beside the form.

### Non-goals

- Do not redesign Source detail or edit dialogs.
- Do not persist credentials, test data, or connector documentation content.
- Do not invent form fields when the connector spec is unavailable.

## User path

1. Open Create source and select a connector from the card list.
2. Continue to the authoring step, enter an id and configuration generated by Formily from the connector spec.
3. Review the connector documentation placeholder and create the Source.

## Data contract

- `GET /api/connectors/:id` exposes `spec.text` verbatim when the connector source is stored.
- The client parses only `configOptions.connection`; malformed or unavailable source produces an actionable in-dialog error instead of falling back to a synthetic schema.
- Normalized `config` metadata remains the payload validator and secret-field classifier.

## Acceptance criteria

- [ ] The create dialog title is left aligned and has no subtitle.
- [ ] The connector picker uses accessible cards with icon, title, and tags before the configuration form.
- [ ] The create form renders the parsed `configOptions.connection` Formily schema, not a schema reconstructed from normalized fields.
- [ ] The desktop form has form and documentation columns and collapses safely on narrow screens.
- [ ] Source detail interaction remains unchanged.
